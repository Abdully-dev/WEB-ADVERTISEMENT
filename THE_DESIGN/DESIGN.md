# DESIGN.md

# Premium Decor & Event Materials Website — Master Design System

## 1. Purpose

This document is the single visual and interaction source of truth for the project.

The website represents a professional decoration business that:

1. Sells decoration materials and equipment.
2. Sells furniture and decorative products.
3. Provides event and interior decoration services.
4. Uses completed decoration work as visual proof of quality.
5. Presents products and spaces through a premium, highly visual digital experience.

The website must feel like a premium visual brand, not a generic business website.

The primary development priority is FRONTEND EXPERIENCE.

Backend functionality is secondary and must not dictate the visual design at this stage.

---

# 2. Core Design Philosophy

The website should communicate:

- premium quality
- craftsmanship
- elegance
- visual confidence
- professionalism
- creativity
- trust
- attention to detail

The design must be:

- image-driven
- spacious
- editorial
- sophisticated
- responsive
- animation-rich but controlled
- commercially useful
- memorable without becoming confusing

The design must NOT feel like:

- a generic WordPress business website
- a SaaS dashboard
- an ecommerce template
- a template marketplace landing page
- an overdecorated wedding website
- a collection of random animations
- an AI-generated UI
- a clone of Apple, Nike, Airbnb, Framer, or any other brand

The goal is to build an ORIGINAL visual identity inspired by established high-quality design systems.

# 8. Global Layout

Use a strong editorial grid.

Desktop:

- large horizontal margins
- generous whitespace
- asymmetrical compositions where appropriate
- strong alignment
- controlled content width
- large visual areas

Avoid:

- excessive centered text
- repetitive three-column cards
- excessive borders
- cramped sections
- equal-sized components everywhere

Not every section needs to follow the same grid.

Visual rhythm is important.

---

# 9. Responsive Design

Design mobile as a first-class experience.

Do NOT simply shrink the desktop design.

Desktop and mobile may use different compositions while maintaining the same visual identity.

Mobile priorities:

1. readability
2. image quality
3. touch interaction
4. navigation simplicity
5. performance
6. animation stability

Interactive elements must have touch-friendly dimensions.

Do not rely exclusively on hover interactions.

---

# 10. Color System

The color system should be restrained.

Use a sophisticated neutral foundation.

Primary palette should generally consist of:

- warm white / ivory
- deep charcoal
- soft black
- warm gray
- muted neutral tones

Accent colors may be introduced sparingly when appropriate to the brand.

Do NOT create a rainbow interface.

Do NOT use excessive gradients.

Do NOT use bright generic SaaS colors.

Color should primarily support:

- hierarchy
- branding
- interaction
- emphasis

not decoration for its own sake.

---

# 11. Typography

Typography should feel editorial and premium.

Use a maximum of:

- one primary display typeface
- one supporting text typeface

A serif/sans-serif combination may be used if it supports the brand.

Typography hierarchy must be obvious:

Display
→ Hero
→ Section heading
→ Subheading
→ Body
→ Caption
→ Metadata

Do not use too many font weights.

Do not use oversized text simply to imitate trendy websites.

Typography must remain readable.

---

# 12. Imagery

- real completed decoration projects

- close-up material details

- lighting
- textures
- room compositions
- before/after transformations where available

Avoid generic stock photography whenever real business photography is available.

Images should be:

- high quality

- compositionally intentional

# 17. Interactive Product Experience

Where technically justified, selected products may receive advanced interactive presentation.

The intended interaction is NOT automatic product rotation.

The desired mental model is:

THE PRODUCT IS STATIONARY.

THE VIEWER MOVES AROUND IT.

The interaction should feel like a person physically walking around a stationary object.

Conceptually:

User drag right
→ viewpoint moves right

User drag left
→ viewpoint moves left

User stops
→ viewpoint stops

The product itself does not rotate.

---

# 18. 3D / Camera-Orbit Experience

For true 3D implementations:

The product remains fixed in world space.

The camera moves around the product.

Example conceptual model:

Product:

position = fixed
rotation = fixed

Camera:

position = changes
orientation = changes

The camera continuously looks toward the product.

Preferred implementation for true interactive 3D:

- WebGL
- Three.js
- React Three Fiber
- GLTF / GLB assets

Use 3D only where it adds meaningful product value.

Do not add 3D merely because it is technically impressive.

---

# 19. Fallback Interactive Experience

If a true 3D model is unavailable, use a carefully generated multi-view asset.

Possible implementation:

36–72 consistent product views.

The frontend maps user drag distance to image frame selection.

User interaction:

drag right
→ advance views

drag left
→ reverse views

stop
→ freeze current view

Important:

The asset itself must NOT automatically rotate.

The frontend controls the displayed view.

# 28. Animation Philosophy

Animation is a major part of this website.

However:

Animation must communicate hierarchy, continuity, or interaction.

It must NOT exist merely to impress the developer.

Use:

- reveal animations
- image masking
- subtle scale
- opacity transitions
- horizontal movement
- parallax
- smooth section transitions
- micro-interactions
- cursor interactions
- page transitions

Avoid:

- excessive bouncing
- random floating elements
- unnecessary spinning
- constant movement
- slow animations that delay usability

---

# 29. Animation Timing

Use consistent motion principles.

Fast:

micro-interactions

Medium:

component transitions

Slow:

hero/section transitions

Motion should generally feel:

- smooth
- deliberate
- physical
- premium

Avoid abrupt linear movement when a more natural easing curve is appropriate.

# 31. Cursor Interaction

PRODUCT
→ "Explore"

PORTFOLIO IMAGE

→ "Drag to explore"

Disable or simplify cursor effects on touch devices.

---

# 32. Hover States

Hover states should communicate interactivity.

Possible behavior:

- subtle image scale
- text movement
- underline animation
- opacity change
- icon movement
- mask reveal

Avoid excessive transformations.

Hover animation should generally complete quickly enough to feel responsive.

---

# 33. Buttons

Buttons should be visually restrained.

Preferred:

- strong typography
- clear contrast
- subtle movement
- clear hover state

Avoid excessive pill-shaped buttons unless consistent with the brand.

Every button must communicate a clear action.

---

# 34. Cards

Cards should NOT be the default solution for everything.

Use cards where content is genuinely modular.

Prefer editorial layouts for:

- portfolio
- hero
- featured products
- major services

Cards may be appropriate for:

- product listings
- testimonials
- structured information

---

# 35. Premium Effects

Premium effects should be selective.

Potential effects:

- magnetic buttons
- image distortion
- smooth parallax
- masked image transitions
- 3D product viewer
- interactive room exploration
- cinematic page transitions
- scroll-linked typography
- layered imagery
- subtle grain/noise
- depth effects

Never implement an effect before proving that it improves the experience.

---

# 36. Grain / Texture

A subtle visual texture may be used to avoid an overly sterile digital appearance.

If used:

- extremely subtle
- low contrast
- never distracting

Do not use obvious noise overlays.

---

# 37. Accessibility

Premium design must remain accessible.

Requirements:

- sufficient color contrast
- keyboard navigation
- visible focus states
- meaningful alt text
- semantic HTML
- reduced-motion support
- accessible form labels
- usable touch targets

When `prefers-reduced-motion` is enabled:

Reduce or disable:

- parallax
- large transforms
- continuous motion
- complex page transitions

The content must remain fully usable.

---

# 38. Performance

Visual quality must not destroy performance.

Prioritize:

- responsive images
- modern image formats
- lazy loading
- appropriate image dimensions
- code splitting
- lazy-loaded 3D
- optimized GLB assets
- reduced animation workload on mobile

Do not load a 3D scene before it is needed.

Do not load massive images when a smaller image is sufficient.

---

# 39. Mobile Rules

Mobile must retain the brand's premium character.

Do not simply stack every desktop element vertically.

Mobile may use:

- horizontal image galleries
- touch-driven interactions
- simplified navigation
- reduced animation
- optimized typography
- smaller image sequences

Interactive product experiences must support touch.

Never depend exclusively on mouse hover.

# 43. Loading Experience

The initial loading state should be minimal.

Possible:

- logo
- subtle progress indicator
- image reveal

Do not create a long cinematic loader.

The visitor should reach useful content quickly.

---

# 44. Error States

Error states must maintain the same visual language.

Do not show default browser-looking errors.

Keep them:

- simple
- readable
- actionable

---

# 45. Design Consistency

Every new component must answer:

1. Does it belong to the visual language?
2. Does it improve usability?
3. Does it support the brand?
4. Does it introduce unnecessary visual complexity?
5. Does it work on mobile?
6. Does it maintain performance?

If the answer is unclear, do not add the component.

---

# 46. Anti-Patterns

NEVER build:

- generic SaaS dashboards
- generic Bootstrap layouts
- repetitive card grids
- excessive rounded rectangles
- random gradients
- excessive glassmorphism
- excessive shadows
- meaningless animations
- autoplay product rotation
- fake testimonials
- fake statistics
- generic stock imagery when real imagery exists
- five different font families
- inconsistent button styles
- inconsistent spacing
- unexplained icons
- excessive decorative blobs

---

# 47. Originality Rule

The project may be inspired by Apple, Nike, Clay, Framer, Pinterest, Airbnb and other design systems.

It must NOT become a visual clone of any of them.

Reference systems provide principles.

This project provides the final identity.

---

# 48. AI Coding Agent Rules

Before modifying the frontend:

1. Read this `DESIGN.md`.
2. Identify the relevant section.
3. Follow the established visual system.
4. Reuse existing components where appropriate.
5. Do not introduce a new design language.
6. Do not invent arbitrary colors.
7. Do not introduce arbitrary typography.
8. Do not add animations without purpose.
9. Do not replace existing visual patterns unnecessarily.
10. Test responsive behavior.

If a design decision is not explicitly defined:

Prefer:

simplicity
+
visual hierarchy
+
brand consistency
+
performance

over adding complexity.
